# Online Shop (Spring Boot + PostgreSQL + Docker)

Полнофункциональное веб-приложение интернет-магазина с аутентификацией пользователей, каталогом товаров, комбинированным поиском, транзакционным оформлением заказов и оптимизацией запросов к БД.

---

## Технологический стек

* **Backend:** Java 25, Spring Boot 4 (Spring Web MVC, Spring Data JPA, Spring Security, Spring Validation)
* **База данных:** PostgreSQL 15 + pgAdmin 4
* **ORM:** Hibernate (автоматическая генерация схемы, управление связями, `@EntityGraph`)
* **Frontend:** HTML5, CSS3, Thymeleaf
* **Инфраструктура:** Docker, Docker Compose, Maven, Lombok

---

## Основной функционал

1. **Аутентификация и безопасность (`Spring Security`):**
  * Регистрация (`/register`) с валидацией полей и хэшированием паролей через `BCryptPasswordEncoder`.
  * Вход по email (`/login`) и защита приватных разделов (оформление и история заказов доступны только авторизованным пользователям).
2. **Каталог товаров и поиск (`/products`):**
  * Связанные сущности `Product` и `Category` (`@ManyToOne(fetch = FetchType.LAZY)`).
  * Автоматическая генерация стартовых категорий и **100 000 тестовых товаров** при первом запуске (`DataInitializer`).
  * Поиск и фильтрация по `ID`, части названия, категории и диапазону цен.
3. **Оформление заказов и транзакции (`/orders`, `/orders/history`):**
  * Поддержка мульти-товарных заказов (`Order` + `OrderItem` с `CascadeType.ALL`).
  * Управление транзакциями через `@Transactional(isolation = Isolation.REPEATABLE_READ)`: контроль остатков на складе, защита от гонки при параллельной покупке и автоматический откат (`ROLLBACK`) при нехватке любого из товаров в чеке.

## Оптимизация БД и Архитектурные паттерны

* **Решение проблемы `N+1` запросов:** Применена аннотация `@EntityGraph` в `ProductRepository` и `OrderRepository`, объединяющая выборку связанных сущностей в один `JOIN`-запрос.
* **SQL-индексы и замер производительности:**
  * На уровне сущности `Product` созданы B-Tree индексы по колонкам `price`, `category_id` и `title`.
  * Реализован структурный паттерн **Decorator** (`TimingProductServiceDecorator`), оборачивающий `ProductServiceImpl` для замера времени выполнения запросов.
  * **Результаты замера поиска по диапазону цен на 100 000 записях:**
    * Без индекса (`Seq Scan`): **18–19 мс**
    * С индексом `idx_product_price` (`Index Scan`): **8–9 мс** *(ускорение более чем в 2 раза)*.
* **Паттерн Observer (Наблюдатель):** При оформлении заказа `OrderServiceImpl` оповещает независимых подписчиков (`EmailReceiptObserver` — отправка электронного чека, `AuditLogObserver` — запись в журнал аудита).

## Запуск проекта в Docker (одной командой)

1. Убедитесь, что запущен **Docker Desktop**, и выполните в корне проекта:
   ```bash
   docker compose up -d --build
   ```
2. Дождитесь инициализации базы и загрузки тестовых данных (отследить можно командой `docker logs -f market_app`).
3. Сервисы будут доступны по адресам:
  * **Интернет-магазин:** `http://localhost:8081`
  * **pgAdmin 4:** `http://localhost:8080` (логин: `admin@admin.com`, пароль: `admin`)
  * **PostgreSQL:** `localhost:5433` (БД: `online_market_db`, пользователь: `market_user`, пароль: `market_password`)
